# Store Automeation

ระบบทะเบียนสินค้าและจัดการคลังอะไหล่อุตสาหกรรม สร้างด้วย PHP, CSS และ JavaScript พร้อมแอป Android

## โครงสร้างโปรเจกต์

- `backend/` — เว็บไซต์ PHP, API, ไฟล์เชื่อมต่อฐานข้อมูล และไฟล์ประกอบของเว็บ
- `frontend/` — โปรเจกต์แอป Android (Gradle)
- `index.php` — เปลี่ยนเส้นทางจาก URL เดิมไปยัง `backend/`
- `Dockerfile`, `render.yaml`, `railway.json` — การตั้งค่า deploy จากราก repository

## โครงสร้างไฟล์

- `backend/index.php` — ภาพรวมสต๊อก จำนวนสินค้า สถานะ รายการรับ–เบิก และหมวดหมู่
- `backend/catalog.php` — ทะเบียนสินค้า ค้นหา/กรอง ดูรายละเอียด และแก้ไขข้อมูล
- `backend/receive.php` — รับสินค้าเดิม หรือเพิ่มสินค้าใหม่พร้อมบันทึกรับเข้าครั้งแรก
- `backend/issue.php` — บันทึกเบิกสินค้าออกและดูประวัติ
- `backend/guide.php` — คู่มือใช้งาน
- `backend/about.php` — หน้าเกี่ยวกับร้านและวิธีใช้งาน
- `backend/config/database.php` — การเชื่อมต่อฐานข้อมูล MySQL `store` (ตั้งค่าแทนได้ด้วย environment variables)
- `backend/data/products.php` — ข้อมูลตั้งต้นกรณีไม่มีฐานข้อมูลเดิม
- `backend/includes/` — โค้ดร่วมของเว็บ การยืนยันตัวตน และการจัดการข้อมูลสินค้า
- `backend/api/` — API สำหรับข้อมูลสินค้าและการซิงก์
- `backend/style.css`, `backend/app.js` — รูปแบบหน้าเว็บและการทำงานฝั่งเว็บ
- `backend/storage/inventory.sqlite` — ฐานข้อมูลเดิมสำหรับย้ายข้อมูลครั้งแรก; หากไม่มีไฟล์ ระบบจะใช้ข้อมูลตั้งต้นจาก `backend/data/products.php`
- `backend/storage/product-images/` — รูปสินค้า JPG, PNG หรือ WEBP ที่อัปโหลด
- `frontend/app/` — ซอร์สโค้ดแอป Android

## วิธีเปิดใช้งาน

**วิธีง่ายสำหรับ Windows/XAMPP:** เปิด MySQL ใน XAMPP แล้วดับเบิลคลิก `start-server.bat` จากนั้นเปิด `http://127.0.0.1:8000` เบราว์เซอร์จะแสดงหน้าเว็บจาก `backend/` โดยไม่ต้องย้ายโปรเจกต์เข้า `htdocs`

หรือเปิด Terminal ในโฟลเดอร์นี้แล้วรัน:

```bash
php -S 127.0.0.1:8000 -t backend
```

คำสั่งข้างต้นต้องใช้ PHP 8 ขึ้นไป, PDO MySQL และ MySQL ที่มีฐานข้อมูล `store` จากนั้นเปิด `http://127.0.0.1:8000` ในเบราว์เซอร์ ห้ามเปิดไฟล์ `index.php` ด้วย `file://` หรือ VS Code Live Server เพราะวิธีเหล่านั้นไม่ประมวลผล PHP

ค่าการเชื่อมต่อเริ่มต้นใน `backend/config/database.php` เป็น MySQL ในเครื่อง (`127.0.0.1:3306`, ฐานข้อมูล `store`, ผู้ใช้ `root`) หากมีรหัสผ่านหรือใช้เครื่องอื่น ให้ตั้งค่า `STORE_DB_HOST`, `STORE_DB_PORT`, `STORE_DB_NAME`, `STORE_DB_USER` และ `STORE_DB_PASSWORD`

### เชื่อมต่อ TiDB Cloud

การเชื่อมต่อฐานข้อมูลทำจากเซิร์ฟเวอร์ PHP ไม่ได้ทำจากมือถือหรือ Google Sheets ให้ตั้ง environment variables บนเซิร์ฟเวอร์ที่เปิดแอป:

- `STORE_DB_HOST`: endpoint ของคลัสเตอร์จากหน้า Connect ใน TiDB Cloud
- `STORE_DB_PORT`: พอร์ตจากหน้า Connect (TiDB Cloud โดยทั่วไปใช้ `4000`)
- `STORE_DB_NAME`, `STORE_DB_USER`, `STORE_DB_PASSWORD`: ฐานข้อมูลและบัญชีที่สร้างใน TiDB
- `STORE_DB_SSL=true`
- `STORE_DB_SSL_CA`: path บนเซิร์ฟเวอร์ไปยังไฟล์ CA certificate ที่ดาวน์โหลดจากหน้า Connect ของ TiDB Cloud

ห้ามใส่รหัสผ่านไว้ในโค้ดหรือส่งผ่านแชต ค่าเหล่านี้ต้องตั้งใน Environment ของบริการที่รัน PHP จากนั้น deploy/restart บริการ เมื่อบันทึกรับหรือเบิก ระบบจะเขียน MySQL ก่อนแล้วจึงส่ง Google Sheets ดังนั้นถ้าชีตได้รับรายการจากแอป แปลว่าแอปเขียนลงฐานข้อมูลที่เซิร์ฟเวอร์กำหนดไว้ แต่อาจเป็นฐานข้อมูลคนละตัวกับ TiDB ที่กำลังตรวจสอบ

## ฟังก์ชัน

- ค้นหาสินค้าด้วยชื่อหรือรหัสและกรองตามหมวดหมู่ในหน้าทะเบียนสินค้า
- ดูรายละเอียดสินค้าและเปิดแบบฟอร์มแก้ไขจากรายการสินค้า
- ลบสินค้าได้จากหน้ารายละเอียด โดยระบบยืนยันก่อนลบสินค้าและประวัติรับ–เบิกที่เกี่ยวข้องอย่างถาวร
- อัปโหลด เปลี่ยน หรือลบรูปสินค้าได้ตอนเพิ่มสินค้าใหม่หรือแก้ไขข้อมูล (JPG/PNG/WEBP สูงสุด 5 MB)
- ข้อมูลสินค้าอยู่ในตารางเดิม `store.product`; ระบบเพิ่มคอลัมน์รหัสสินค้าเพื่อรองรับการเชื่อมต่อ
- ประวัติรับและเบิกอยู่ในตาราง `store.receipts` และ `store.issues`
- เมื่อตาราง `store.product` ว่าง ระบบจะนำข้อมูลและประวัติจาก SQLite เดิมเข้าฐานข้อมูล MySQL เพียงครั้งเดียว และจะไม่เขียนทับตารางที่มีสินค้าอยู่แล้ว
- ทะเบียนสินค้าใช้ดูและแก้ไขรายละเอียด; เพิ่มสินค้าใหม่จากหน้ารับสินค้าโดยบันทึกยอดรับครั้งแรกพร้อมกัน
- เลือกหมวดหมู่/ประเภทจากรายการ และเลือกหน่วยนับเป็นชิ้นหรืออัน
- ยอดคงเหลือคำนวณจากยอดรับสะสม − ยอดเบิกสะสม
- แสดงแดชบอร์ดจำนวนสินค้า รายการรับ–เบิก สถานะสต๊อก และจำนวนแยกตามหมวดหมู่ที่กำหนด โดยแสดง 0 เมื่อยังไม่มีสินค้าในหมวดนั้น
- บันทึกรับเข้าและเบิกออก พร้อมผู้เกี่ยวข้อง เอกสาร หมายเหตุ และประวัติย้อนหลัง
- ข้อมูลตั้งต้นนำประวัติรับ/เบิกจาก Excel มาแสดง โดยรายละเอียดที่ไม่มีในไฟล์ต้นทางจะเว้นว่าง
- เบิกเกินยอดคงเหลือได้ตามรูปแบบเดิมใน Excel และแสดงสถานะสต๊อกติดลบ
- คู่มือการใช้งานและขั้นตอนสำรองฐานข้อมูล

ระบบต้องมี PHP PDO MySQL และ Fileinfo เปิดใช้งาน พร้อมสิทธิ์สร้าง/แก้ไขตารางในฐานข้อมูล `store` และเขียนไฟล์ใน `backend/storage/product-images/` การเชื่อมต่อครั้งแรกจะเพิ่มคอลัมน์ที่จำเป็นในตาราง `product` และสร้างตารางประวัติรับ/เบิก หากต้องการย้ายข้อมูลเดิม ให้วางไฟล์ `backend/storage/inventory.sqlite` ไว้ในเครื่องก่อนเปิดระบบ; ไฟล์ฐานข้อมูลและรูปสินค้าที่อัปโหลดถูกยกเว้นจาก Git เพื่อป้องกันการเผยแพร่ข้อมูลภายใน หลังย้ายข้อมูลแล้ว ฐานข้อมูล MySQL `store` เป็นแหล่งข้อมูลหลัก

ไฟล์ Excel ต้นทางไม่มีข้อมูลราคา เว็บไซต์จึงไม่แสดงหรือสมมติราคา แก้ไขรายละเอียดสินค้าผ่านหน้า `backend/catalog.php` และจัดการสต๊อกผ่านหน้า `backend/receive.php` และ `backend/issue.php`; `backend/products.php` จะเปลี่ยนเส้นทางไปยังทะเบียนสินค้าเพื่อรองรับลิงก์เดิม ส่วน `backend/data/products.php` ใช้เป็นข้อมูลตั้งต้นเมื่อไม่มีข้อมูล SQLite เดิมให้ย้ายเท่านั้น
